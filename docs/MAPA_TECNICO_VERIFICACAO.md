## Fluxo de dados

**Entrada bruta → hazard raster (1 km, EPSG:4326, `config.RESOLUTION_TARGET_DEG=0.008333`):**

- `data/raw/climate/aqueduct/{country}/aqueduct_2050.csv` (WRI Aqueduct 4.0 `future_annual`, via GEE) → `water_stress_processor.py` / `water_variability_processor.py` → `ws` (water stress), `sv` (seasonal variability), `iv` (interannual variability) rasters, grid = heat grid `[doc: DECISIONS#"Water stress output grid = the extreme-heat grid"]`.
- `data/raw/climate/cds_tasmax/{country}/{model}/{scenario}/` (CMIP6 daily `tasmax`, GFDL-ESM4 + MIROC6, ssp126/ssp370/ssp585) → `heat_stress_processor.py` → `extreme_heat_days_{country}_{model}_{scenario}_1km.tif` (days/yr tasmax>40°C).
- `data/raw/climate/cds_spei/` (daily `pr`+Thornthwaite PET) → `src/processors/spei_processor.py` → `spei` raster (months/yr SPEI-12 ≤ -1.0).
- `data/raw/climate/cds_precipitation/` (daily `pr`, mesma série do SPEI) → `src/processors/extreme_precipitation_processor.py` → `precip` raster (dias/ano acima do P95 local de dia úmido) `[código: extreme_precipitation_processor.py]`.
- `data/raw/climate/era5_wind/{country}/{year}/annual_max.nc` (ERA5 hourly gust, 1991-2020, 90/90 arquivos) → `extreme_wind_processor.py::compute_mean_annual_max_gust` → `extreme_wind_gust_raw_{country}_1km.tif` (média de 30 máximos anuais, m/s).
- GEM Global Integrated Power Tracker (`gem_global_integrated_power_tracker_20260809.xlsx`, snapshot 2026-08-09) → `gem_validated_plants_{country}.csv` (agregação por planta, `fuel_type_bucket` ∈ {hydro,thermal,wind,solar}).

**Índice (todos em `src/index/`):**

- `risk_calculator.py::compute_risk_by_hazard` — amostra cada raster no ponto da planta (`sample_raster`), aplica transform (`transform_term`: `Tlog=-ln(1-x)` para `LOG_TERMS={ws,heat,spei,wind}`*, `Tlin`=Min-Max direto para `LIN_TERMS={sv,iv,precip}`) sobre `FROZEN_BOUNDS` (min/max empírico pooled, por-GCM para heat/spei/precip, flat para ws/sv/iv/wind), e computa `Risk_{i,h} = Hazard_{i,h} × Exposure_i(MW) × Vulnerability_i(age_factor)` (Equação 1, sem soma entre hazards). Saída: `data/outputs/tables/risk_by_hazard.csv` (78,497,736 bytes, mtime 2026-09-16 07:12).
  *nota: `spei` foi movida de `LOG_TERMS` para `LIN_TERMS` em 2026-09-14 (skew empírico 0.36/0.13 < 0.5).
- `age_factor.py::compute_age_factors` — `age_factor = 2 - clip(retention(age),0,1)`, `age = 2050 - commissioning_year`. Saída: `ccrs_age_factors.csv` (1,498,540 bytes, mtime 2026-09-04 20:16 — pré-data do rework v3; reaproveitado sem recálculo, pois a fórmula de age_factor não mudou desde 09-04).
- `risk_bands.py::compute_risk_bands` — classifica cada (planta, hazard aplicável) em banda discreta (`Low/Medium/High/Extreme`, ou `Low/Extreme` para Wind-bucket) a partir do valor bruto (não normalizado), usando `hazard_scope.APPLICABLE_HAZARDS` como fonte única de H_b. Saída: `risk_bands.csv` (12,196,690 bytes, mtime 2026-09-16 07:13).
- `psae.py::compute_psae` — agrega `RiskBand_{i,h}` dentro de H_b em `PSAE_i = (1/|H_b|)·Σ 1[RiskBand≥High]` (Equação 2), complete-case (NaN se qualquer hazard do H_b da planta estiver ausente). Saída: `psae.csv` (3,569,443 bytes, mtime 2026-09-16 07:16).
- `contextual_validators.py` — camada de validação contextual (não retroalimenta Risk/RiskBand/PSAE; guarda de read-only testado). Saída: `contextual_validators.csv` (6,739,663 bytes, mtime 2026-09-15 07:34).
- `correlation_gate.py::run_gate` — roda sobre valores BRUTOS pré-normalização, gate |r|≥0.80 sobre 5 pares candidatos + 1 par report-only. Saída: `correlation_gate.csv` (regenerado 2026-09-16 11:54, 56 linhas, 0 "fail", 36 "pass", 6 "report_only", 14 sem verdict/pooled).
- `sobol_sensitivity.py` / `general_mc.py` / `scenario_discovery.py` / `sensitivity_recompute.py` / `rng_utils.py` — camada de sensibilidade (Fase 6), consome cache de `sensitivity_recompute.precompute()` (raster sampling feito uma vez), nunca recalcula raster por draw. Saídas: `phase6_sobol_full_n1024.json` (774,061 bytes, mtime 2026-09-15 13:06), `phase6_general_mc_convergence.json` (38,897 bytes, mtime 2026-09-15 16:26).

**Reporting (`src/reporting/results_draft/item01..16 + run_all.py`)** consome os CSVs acima (nunca recalcula hazard/risk/PSAE) e escreve em `data/outputs/results_draft/{tables,maps,other}/` mais `MANIFEST.md` (16/16 itens gerados, 80 arquivos nesta execução).

`RiskBand_{i,h}` é persistido em `risk_bands.csv`; `PSAE_i` em `psae.csv`; `Risk_{i,h}` em `risk_by_hazard.csv` — três tabelas separadas, nunca fundidas num único "score combinado" (isso é intencional: Equação 1 é definida por-hazard, nunca somada entre hazards `[doc: DECISIONS#"GEAR v3 Phase 1: Risk_i,h replaces the CCRS core (Equation 1)"]`).

### Normalização e transforms (água/calor pré-v3, herdados)

- **[2026-09-03] Normalização de água**: per-country Min-Max, 3 cenários Aqueduct pooled — nunca cross-country; camada raw é o input do índice, camada normalizada é produto standalone.
- **[2026-09-03] Sentinela WRI 9999**: excluído do cálculo de max, substituído pelo max real per-country em ambas as saídas (normalizada e bruta); nunca removido do dataset. Medido: 34 entradas sentinela na Índia, 0 em Brasil/Portugal.
- **[2026-09-03] Grade de saída água = grade de calor**: evita desalinhamento de ponto-flutuante entre camadas de hazard `[código: water_stress_processor._load_reference_grid]`.
- **[2026-09-03] Normalização de calor**: Min-Max per-country pooling conjunto de modelos+cenários (nunca cross-country); guarda `GridMismatchError` (não passagem silenciosa) se rasters de modelos divergirem em grade.
- **[2026-09-03] Camada bruta de calor = passthrough do downloader**: sem cópia/recomputação `[código: heat_stress_processor.raw_raster_path]`.
- **[2026-09-03] Combinação linear de hazard, sem termo de interação**: correlações Spearman água×calor medidas (~-0.45 BR, +0.08 PT, +0.41 IN) refletem colocalização geográfica, não mecanismo físico documentado — ajustar termo de interação a esse padrão amostral seria erro de categoria.
- **[2026-09-04] Bounds Min-Max globais congelados**: `heat`/`spei`/`precip` per-GCM (nunca blend GFDL-ESM4/MIROC6); `ws/sv/iv/wind` flat (sem eixo GCM, um par único pooled). Snapshot 2026-09-04, estendido (não redefinido) para spei (09-04) e precip (09-13) e wind (09-14) `[código: risk_calculator.FROZEN_BOUNDS]`. **Reaberto 2026-09-14, fechado no mesmo dia**: confirmado via Table S3 do artigo publicado que `FROZEN_BOUNDS` é min/max empírico pooled, sem percentil — nenhum percentil de bounds existe na pipeline; `D` do Sobol revisado de 7→6 (posteriormente 13, ver Fase 6).
- **[2026-09-11] Neg-log transform (`-ln(1-x)`) substitui log1p**: decisão de autor (não assumida), aplicada a todo `LOG_TERMS` — log1p comprime exatamente a cauda onde uma planta fisicamente extrema deveria estar mais separada; `-ln(1-x)` expande `[código: normalization.py::transform_neg_log_minmax; risk_calculator.py::transform_term]`. Critério de seleção: skewness Fisher-Pearson, `|skew|>0.5` (Bulmer 1979 [NÃO VERIFICADO]) decide, Shapiro-Wilk é diagnóstico apenas.
- **[2026-09-14] `precip` classificado em `LIN_TERMS`**: skew empírico não é right-skew (GFDL -0.125, MIROC6 -0.586) — decidido pelo shape real, não por paridade assumida com ws/heat/spei.
- **[2026-09-14] `wind` classificado em `LOG_TERMS`**: skew empírico +0.6215 (right-skewed) — mesma regra empírica de `precip`, resultado diferente por dado diferente.
- **[2026-09-14] Fase 3.3 aplica `-ln(1-x)` a TODO `LOG_TERMS` atual, incluindo `wind`** (Opção B, decisão de autor) — `wind` não ganha exceção especial.
- **[2026-09-14] `spei` reclassificado `LOG_TERMS`→`LIN_TERMS`**: herdado sem reavaliação desde o design CCRS; skew real 0.36/0.13 (<0.5) confirmado por Table S3 publicada — corrige divergência código/artigo.

### Arquitetura do índice (v3, Equação 1 em diante)

- **[2026-09-11] Risk_{i,h} substitui o núcleo CCRS**: `Risk_{i,h}=Hazard_{i,h}×Exposure_i×Vulnerability_i`, por hazard, nunca somado entre hazards; `EventMultiplier` removido do núcleo (módulo mantido, não usado) `[código: risk_calculator.py]` `[doc: DECISIONS#"GEAR v3 Phase 1: Risk_i,h replaces the CCRS core (Equation 1)"]`.
- **[2026-09-11] Extreme Precipitation processor**: Tier 3 apenas, percentil P95 de dia úmido (ETCCDI/Zhang et al. 2011 [NÃO VERIFICADO]) por pixel — reusa série `pr` do SPEI, sem novo download.
- **[2026-09-11] Wildfire deferido**: sem processor implementado, formalizado como limite de escopo declarado (ver Limitações).
- **[2026-09-11] Thermal bucket homogêneo**: sem split por tecnologia de resfriamento — consequência de código do achado Fase 0.1.
- **[2026-09-11] Extreme Wind processor (ERA5 gust)**: um raster bruto (média de máximo anual de rajada), dois consumidores de threshold via dispatcher (`classify_extreme_wind`): Wind-bucket Tier 1 (IEC ~25m/s) vs Solar-bucket Tier 3 (percentis P75/90/95/99).
- **[2026-09-11] Módulo de normalização isolado**: `normalization.py` produz recomendação, não altera `risk_calculator.FROZEN_BOUNDS`/`transform_term` diretamente — Fase 3.3 aplica depois.
- **[2026-09-11] Solar Extreme Wind — percentil ERA5 é final, não contingência**: sem valor Tier 1 defensável para uplift estrutural de tracker solar (ASCE 7 é site-specific por construção; fabricantes variam ~51-60+ m/s).
- **[2026-09-11] ERA5 retido como fonte de Extreme Wind, substituição CMIP6 rejeitada**: nenhum `sfcWindmax`/gust existe no catálogo CMIP6 para os 2 GCMs; `sfcWind` diário-médio é fisicamente incompatível com rajada instantânea ERA5 sem fator de rajada não validado; corroborado por IPCC AR6 WGI Cap.11 ("low confidence" em extremos de vento projetados) [NÃO VERIFICADO diretamente — citação de relatório, não verificada linha a linha por este mapa].
- **[2026-09-11] Par de GCM (GFDL-ESM4, MIROC6) — documentação retroativa**: ECS ~2.6-2.7K e 2.6K respectivamente (Dunne et al. 2020, Tatebe et al. 2019, Zelinka et al. 2020 [NÃO VERIFICADO]) — ambos próximos, não formam par de bounding por sensibilidade climática; escolha de MIROC6 foi operacional (divergência estrutural qualitativa), não baseada em ECS.
- **[2026-09-11] Extreme Wind reenquadrado como exposição estrutural invariante a cenário**: posição epistêmica assentada, não placeholder — não reaberto pela mera aparição futura de produto CMIP6 gust isolado.
- **[2026-09-11] Gas/oil-gas `age_factor=1.0` confirmado final**: busca limitada não encontrou curva Tier 1/2 citável por idade calendário; evidência de fleet-level (Grubert 2020 [NÃO VERIFICADO]) mostra sinal oposto (melhora com idade), mas confundida com retrofit/dispatch — não usável como curva.
- **[2026-09-12] Tie-breaker do correlation gate pré-registrado**: hierarquia de 3 critérios (primazia mecanística → confiança de tier → sv/iv específico, retém iv sobre sv) fixada ANTES de rodar o gate sobre dado real, para evitar p-hacking na retenção de variável.
- **[2026-09-12] Correlation gate implementado e rodado**: raw pré-normalização, Pearson padrão + Spearman sempre computado, proxy de não-linearidade `|rho|-|r|>0.10` (disparou em 4/48 células reais); por país nunca pooled para decisão; **nenhuma exclusão** — maior `|r|` observado 0.702 (sv×iv, Hydro, Portugal) `[código: correlation_gate.py]`; `data/outputs/tables/correlation_gate.csv`.
- **[2026-09-12] Extreme Precipitation processado para Portugal/Índia, gate fechado para os 3 países**: nunca executado antes para esses 2 países (confirmado, não presumido); reprocessamento limpo 12/12 combinações.
- **[2026-09-12] `hazard_scope.py` reconciliado após conflito de sessões paralelas**: H_b final — Hydro {ws,spei,precip,sv,iv} (5); Thermal {ws,heat,precip} (3, sv/iv excluídos por ausência de campo de tecnologia de resfriamento); Wind {wind} (1); Solar {heat,precip,wind} (3) `[código: hazard_scope.APPLICABLE_HAZARDS]`.
- **[2026-09-12] RiskBand_{i,h} — tabela consolidada de tier/threshold**: Water Stress Tier 1 (cortes absolutos WRI 0.1/0.4/0.8); Drought/Extreme Precip/sv/iv Tier 3 (percentis pooled P75/90/95, P50 diagnóstico); Extreme Heat Thermal Tier 3; Extreme Wind Wind-bucket Tier 1 binário (IEC ~25m/s); Extreme Wind Solar-bucket Tier 3 (P90/95/99). - **[2026-09-14] `psae.compute_psae` vetorizado**: elimina groupby Python por (planta, cenário) — 110x mais rápido nesse passo isolado (~7.9s→~0.25s), output verificado byte-idêntico por duas vias independentes.

- **[2026-09-03] SLR excluído do conjunto de hazards.** Razão: nenhuma base empírica defensável (coeficientes por-tecnologia de inundação costeira/storm-surge) para a frota terrestre estudada. Status: Revisitable — "extensão natural quando coeficientes por-tecnologia estiverem disponíveis" `[doc: LIMITATIONS#"2026-09-03 — Sea-level rise (SLR) excluded from the hazard set"]`.
- **[2026-09-04] Pesos por-bucket água/calor/seca: julgamento de autor, não calibração.** Nenhuma razão de importância relativa água/calor/seca publicada existe na literatura para nenhuma dessas tecnologias. Tier 3. Status: Revisitable, flagged como candidato de sensibilidade Monte Carlo.
- **[2026-09-11] Campo GEM de tecnologia de resfriamento ausente: bucket Thermal tratado como homogêneo.** Nenhum campo sob qualquer nome no GEM Global Integrated Power Tracker para Brasil/Portugal/Índia. Status: Final a menos que uma futura release GEM adicione o campo. Declarado explicitamente no manuscrito como provável superestimação de risco de estresse hídrico para a fração dry-cooled dentro de Thermal.
- **[2026-09-11] Campo GEM de retrofit/repowering ausente.** `age_factor`'s coal overhaul cycle (ciclo de 5 anos, recuperação de 70%) é premissa de modelagem assumida, não derivada de fonte real de histórico de overhaul. Status: Revisitable.
- **[2026-09-11] Extreme Precipitation: threshold absoluto HAZUS-MH rejeitado, Tier 1 rebaixado a Tier 3.** Os valores de profundidade de inundação (0.2/0.5/1.5m) rascunhados não existem no manual técnico primário FEMA Hazus Flood Model; HAZUS-MH usa curvas contínuas profundidade-dano por tipo de ocupação, não classes discretas. Status: Final neste tier.
- **[2026-09-11] Solar Extreme Wind: nenhum threshold estrutural Tier 1 existe; percentil de rajada ERA5 é final.** ASCE 7 é site-specific por construção; ratings de sobrevivência de fabricante variam ~51-60+ m/s. Status: Final, não contingência — explicitamente declarado como não pendente de valor Tier 1 futuro.
- **[2026-09-11] Wildfire (FWI/EFFIS) deferido, não implementado.** Umidade relativa próxima à superfície diária, necessária para FWI canadense auto-computado, ausente do catálogo CDS `projections-cmip6` para ambos GCMs configurados sob qualquer cenário; fonte global alternativa checada (ETH Zurich FWI-CMIP6, Quilcaille et al. 2023 [NÃO VERIFICADO]) tem zero cobertura GFDL-ESM4 e fornece só indicadores anuais relativos a período de referência, não FWI diário ou classes compatíveis com EFFIS. Status: mesmo tratamento da exclusão SLR — deferido, trabalho futuro se fonte de dado aparecer.
- **[2026-09-11] Extreme Wind: baseline histórico ERA5, invariante a cenário por design.** Extreme Wind é o único hazard originado de reanálise histórica ERA5 (1991-2020) em vez de projeção SSP CMIP6; sua contribuição a `Risk_i,h`/RiskBand/PSAE é idêntica através das três colunas SSP. Nenhuma variável CMIP6 daily-maximum ou gust existe no catálogo CDS para nenhum dos dois GCMs configurados, e a variável diária que existe (`sfcWind`, média diária) não é a mesma quantidade física da rajada instantânea ERA5 que este hazard usa — converter entre elas requer parametrização de fator de rajada não validada e dependente de condição. IPCC AR6 WGI Capítulo 11 atribui independentemente "baixa confiança" a mudanças projetadas de vento severo pelas mesmas razões de resolução/parametrização. Status: **Final — posição epistêmica assentada, não placeholder.** Explicitamente não reaberto como item "TODO: encontrar dado de vento melhor". Mesmo um futuro produto CMIP6 daily-maximum/gust resolveria só um dos dois fundamentos independentes de rejeição e não reabriria isso por si só.
- **[2026-09-12] Extreme Wind: input de rajada ERA5 ainda não baixado para nenhum país (status de aquisição, aberto).** `data/raw/climate/` não tinha diretório `era5_wind/` para nenhum país; `extreme_wind_processor.py` código-completo e testado unitariamente (14 testes, monkeypatched), mas nunca produziu raster processado real para nenhum país. **[Nota: esta limitação foi posteriormente fechada — ver entradas de 2026-09-14 abaixo, que a esta atualiza sem substituir.]**
- **[2026-09-11] Par de GCM (GFDL-ESM4, MIROC6): seleção operacional, não design de bounding por ECS.** O par não é um design de bounding por sensibilidade climática: GFDL-ESM4 (ECS ~2.6-2.7K) e MIROC6 (ECS 2.6K) situam-se lado a lado perto da extremidade baixa da faixa ECS CMIP6 (~1.8-5.6K) e não a cobrem. A seleção original de GFDL-ESM4 como modelo único/primário antecede inteiramente o registro de decisões deste projeto e não tem justificativa registrada. Status: Final como questão de documentação/enquadramento — não reabre a escolha do par V4 e não autoriza adicionar, remover ou substituir nenhum dos dois modelos.
- **[2026-09-11] `age_factor` gas/oil-gas: fixado neutro, confirmado final após busca bibliográfica limitada.** Plantas termelétricas a gás e oil-gas recebem `age_factor=1.0` (neutro) — diferentemente de carvão (decaimento sawtooth por ciclo de overhaul), hidro, eólica e solar, que têm curvas de retenção baseadas em literatura. Busca limitada não encontrou curva de degradação por idade citável Tier 1/Tier 2 para turbinas a gás/ciclo combinado análoga a Kim & Moon (2012)/Sagaf (2020) [NÃO VERIFICADO]. Literatura de degradação de engenharia reporta perda em termos de horas-operacionais-firing (dominada por fouling recuperável de compressor), não em termos de idade calendário. Evidência longitudinal em nível de frota (Grubert, 2020, *IOPSciNotes* [NÃO VERIFICADO]) encontrou o sinal OPOSTO em nível de frota: plantas a gás dos EUA rodaram mais, e mais eficientemente, conforme envelheceram — atribuível a retrofits, mudanças de despacho e efeitos de vintage, não a mecanismo puro de degradação por idade. Status: **Final, não mais pendente.**
- **[2026-09-13] Extreme Wind: nenhum Risk_{i,h} (Equação 1) ainda, não apenas gap de RiskBand.** `risk_calculator.py`'s `HAZARD_TERMS`/`FROZEN_BOUNDS` não incluíam `wind` — nenhuma planta/bucket/país tinha valor contínuo de `Risk_{i,h}` para Extreme Wind. **[Nota: fechado em 2026-09-14, ver Decisões Vigentes.]**
- **[2026-09-14] Extreme Wind: aquisição de rajada ERA5 completa para os três países (gap de Risk_{i,h} inalterado, ainda aberto na data desta entrada).** Brasil 30/30, Portugal 30/30, Índia 30/30 anos cacheados, verificado por contagem direta de arquivo e passe de integridade de arquivo (todos os 90 arquivos abrem limpo, sem grades all-NaN, sem valores fora de faixa). **[Nota: o gap de Risk_i,h citado foi fechado na mesma data, "GEAR v3 wind Risk_i,h integration".]**
- **[2026-09-15] Validador de ocorrência física IBTrACS: proxy de raio fixo, não dado real de campo de vento por tempestade.** O estado `Corroborated`/`No Record` do `contextual_validators.compute_physical_occurrence_validation` para o termo de hazard `wind` é decidido por uma distância great-circle fixa de 100km do ponto da planta a qualquer ponto de trilha qualificante (`STORM_TRACK_RADIUS_KM`), não pela extensão de campo de vento real de cada tempestade. Um ponto de trilha sem velocidade de vento reportada por `WMO_WIND` nem `USA_WIND` não pode ser avaliado contra o piso de força de vendaval (`IBTRACS_MIN_WIND_KT=34`) e é silenciosamente excluído de todo match — mesma postura "excluído, não contado como ausência do hazard" que a própria lacuna de cobertura EM-DAT já carrega neste módulo. Arquivos CSV de bacia são o produto "final" da NOAA, atualizado aproximadamente duas vezes por ano — uma tempestade dos últimos meses antes da aquisição pode estar sub-revisada ou brevemente ausente frente ao produto quase-tempo-real. Status: Revisitable.
- **[2026-09-15] Escopo de mapeamento de hazard Fase 5: landslide/lightning excluídos, mapeamento Storm/Flood ainda aberto (não completo).** A camada de validador contextual da Fase 5 não cobre o espectro completo de tipo de desastre EM-DAT. (1) **Landslide e lightning são excluídos inteiramente** — nenhuma fonte de ocorrência física é adquirida para nenhum dos dois, e nenhum dos dois hazards é investigado para mapeamento tipo-de-desastre/termo-de-hazard. (2) Dos hazards que são cobertos, o mapeamento tipo-de-desastre→termo-de-hazard é ele mesmo incompleto: `Flood` mapeia para `ws` (Water Stress), não `precip` (Extreme Precipitation) — **[Nota: esta parte foi superseded em 2026-09-15 pela entrada de Hazard Mapping Proxies abaixo, que muda Flood→precip e adiciona Storm→wind; landslide/lightning permanecem excluídos e inalterados.]** Fase 5 é portanto **parcial, não funcionalmente completa**, para ambas as classes.
- **[2026-09-15] Hazard Mapping Proxies (Fase 5): Flood→precip, Storm→wind (decisão de autor).** O mapeamento tipo-de-desastre→termo-de-hazard do validador broad-impact EM-DAT agora atribui `Flood→precip` (antes `Flood→ws`) e adiciona `Storm→wind` (antes sem mapeamento). Ambos são suposições de proxy, não correspondências exatas de causa de desastre: **Flood** — usar precipitação como proxy de inundação exclui causas de inundação não-meteorológicas (ex.: falha de barragem, degelo rápido) da corroboração. **Storm** — usar vento como proxy de tempestade consolida volume de dado num único termo de hazard real (`wind`), mas carrega ruído metodológico inerente: a própria categoria `Storm` do EM-DAT não separa dano de infraestrutura causado por rajadas de vento de dano causado por inundação concorrente no mesmo evento. Status: Ativo. Revisitable se EM-DAT adicionar detalhe de sub-causa.
- **[2026-09-16] Camada legada CCRS de visualização/sensibilidade removida** (`src/index/monte_carlo.py`, `src/visualization/{charts,tables,data,maps}.py`, `analysis/ccrs_capacity_by_score_band.py`). Deletada, não deixada quebrada no lugar. Confirmado não alcançável de `src/reporting/results_draft/` nem de nenhum script `analysis/*.py` ativo. Status: Final para a camada deletada em si; revisitable só se uma futura fase decidir reconstruir visualizações nativas v3 reusando esta lógica de plotting como referência.
- **[2026-09-16] `src/index/sensitivity_recompute.py` (Fase 6): infraestrutura de recomputação, não um resultado de sensibilidade.** Implementa apenas a otimização de cache/recomputação-parcial de raster que `PHASE6_DESIGN.md` Seção 4.2 propôs. Não roda Sobol, não amostra de SALib, não produz nenhum índice, ranking ou estatística de convergência de sensibilidade. Não deve ser citado como, ou confundido com, a análise de sensibilidade do projeto. Status: Final como declaração de escopo.
- **[2026-09-16] `src/main.py`: mantido na árvore, não migrado para o pipeline v3 (`risk_calculator`).** `src/main.py`, o orquestrador pré-v3, ainda importa os símbolos deletados `ccrs_calculator`/`ccrs_report` e falha em tempo de import/chamada.
